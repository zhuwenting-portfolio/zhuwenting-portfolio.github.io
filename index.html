军职 App 智能问答与资源推荐

意图分流 · 知识库约束 · 推荐结果校验

面向 App 中“咨询问题”和“查找学习资源”并存的场景，参与构建从意图理解、知识库检索到答案生成与资源推荐的 LLM 工作流，使不同任务进入对应处理分支。

  • 任务分流：区分智能对话、常见问题问答，以及课程、文章、音频、电子书推荐，将用户问题送入对应工作流。

展开实现细节与流程说明

01 / 把不同请求送到对应分支

用户可能询问 App 的常见功能，也可能要求推荐课程。参与根据业务场景和 Query 语义设计分流规则，把智能对话、FAQ 和四类资源推荐分别处理，使后续检索对象、Prompt 和输出结构与任务相匹配。

02 / 用检索内容约束回答

问答分支将知识库召回内容作为回答依据，Prompt 明确可使用的知识范围及回复要求。这样，模型在业务问答中有具体材料可参考，生成过程也能围绕已有知识展开，而不是仅凭模型内部知识组织答案。

03 / 将推荐限制在候选集内

推荐分支先获得带资源 ID 的候选列表，再由大模型根据问题语义筛选相关资源。设计候选集约束和 ID 白名单过滤：模型输出的每个 ID 都要属于本次可用资源集合，减少不存在的课程、文章或资源编号进入结果。

04 / 统一 App 可消费的协议

按约定生成 type、rsType、rsIds 等字段，表达交互类型、资源类型与资源 ID 列表。通过 JSON Schema 检查字段和数据类型，再对 ID 进行业务校验。JSON 格式正确和资源真实存在分别检查，才能让下游按统一结构处理。

05 / 数量意图与异常处理

解析“推荐两门”“给我几篇”等数量要求，结合 Top-K 裁剪控制结果规模；对重复资源去重，对格式异常、候选不足或无有效结果设置兜底处理。不同分支都经过输出校验，避免将未经处理的模型原文直接作为推荐结果。

06 / 一个请求如何流转

示例：“推荐两门沟通技巧课程。”先识别为课程推荐，再检索相关课程，将候选内容交给推荐 Prompt；返回的 rsIds 经白名单检查与去重后，最多保留两项。示例展示链路含义，不代表线上实测或真实课程数据。

展开实现细节与实验结果

01 / 先建立可比较的实验输入

将 5 份法律 DOCX 文档整理为 TXT，配置基础 FAISS 向量 RAG、LightRAG 和 GraphRAG SDK，使用同一语料、本地 BGE-M3 向量服务及统一测试问题。比较的重点是不同检索与组织方式下的问答质量和调用耗时。

02 / 让法律文本适配测试集生成

默认按标题提取和切分的流程不适合法律条文，生成时出现异常。改为按“第×条”组织文本，绕过不适用的默认标题处理，为条文片段准备节点内容与关键词，供 RAGAS 的单跳问题生成流程使用。这里的节点是测试集生成所需结构，不等同于已建设完整法律知识图谱。

03 / 修复中文角色与生成中断

内部角色返回 Laborer，而配置使用“劳动者”时，按名称查找会失败；统一角色标识并保留中文角色描述。调整中文问题与参考答案 Prompt，配置输出长度、超时和重试参数，处理长输出截断及生成中断，最终形成 50 条问答样本。

04 / 把各框架结果整理成同一种格式

统一保存 user_input、response、retrieved_contexts、reference 四类字段。对未随回答返回检索上下文的 GraphRAG SDK，通过额外调用原生 retrieve 接口采集检索结果用于评测；该步骤是独立检索调用，不能将其视作生成调用实际消费上下文的完整记录。

05 / 分开观察检索与回答质量

使用忠实性、回答相关性、上下文精确率、上下文召回率、事实正确性和语义相似度六项指标，并记录耗时。检索评价关注“找回的材料是否相关、依据是否充分”，回答评价关注“是否回答问题、是否与依据和参考答案一致”。

06 / 排查异常并解释实验差异

检查评测中出现的 NaN，针对缺失指标复查和补评，区分评测调用失败与模型实际低分。实验中，基础向量 RAG 耗时较低；LightRAG 的回答相关性较高；GraphRAG SDK 的忠实性较高，但上下文精确率较低，提示应结合检索冗余和业务目标选择方案。

大新银行贸易单据模板匹配服务

PDF 多页解析 · 双路语义向量 · Elasticsearch 相似度检索

面向贸易单据分类与模板匹配需求，将输入 PDF 转为页面图片，利用 VLM 提取文字和内容描述，再构建双路语义向量。通过与已标注模板比较相似度，为新单据返回最匹配的模板结果。

  • 服务封装：使用 FastAPI 提供建库、模板新增、删除和检索 4 类接口，衔接 PDF 处理、文件服务、VLM、Embedding 与 ES。
  • 文档表示：提取页面文字与视觉内容描述，两路文本分别经 BGE-M3 编码为 1024 维向量，并按页聚合为文档表示。
  • 匹配与写入：通过加权余弦相似度返回 Top-1 模板；新增前检查模板 ID，并用原子创建处理并发写入冲突。

展开实现细节与流程说明

01 / 业务接口与模板库

将算法组织为一个 FastAPI 服务，提供 /index/create、/index/add、/index/delete 和 /index/search。index_name 用来选择模板库；新增模板时，调用方提供 pdf_id、PDF 地址和类别标签。服务按指定索引读写 ES，账号与模板库的归属由上层业务系统管理。

02 / PDF 转图与文件流转

接口接收 PDF URL 后，先将文件下载到算法服务机器临时处理，再通过 PyMuPDF 按页渲染为 PNG。PNG 上传到文件服务后得到图片 URL；后续图像处理模块按 URL 取图。正常处理完成后清理本机临时文件，文件服务负责保存已上传图片，ES 负责保存模板记录。

03 / Base64 与 VLM 结构化提取

图像模块下载 PNG，将图片字节编码为 Base64 data URL，随模型请求提交。Base64 是图片的传输表示，避免本次请求依赖模型侧再访问图片 URL。通过 Prompt 要求 VLM 输出 text_content（页面文字）和 vision_content（图片内容描述）两个字段。

04 / 双路编码与跨页聚合

分别将页面文字和内容描述送入 BGE-M3 Embedding 服务，得到两个 1024 维向量。多页文件在每一路内收集有效页面向量并取均值，形成一对文档级向量。ES 记录保存模板 ID、标签、双路向量及有效性标记，不直接存入 PDF、PNG 或 Base64 文件内容。

05 / 检索打分与模板匹配

待识别 PDF 经过相同特征处理后，与指定模板库中的记录计算相似度。默认按文字 0.4、内容描述 0.6 加权，将各自余弦分数加 1 后融合，取最高分模板。实现采用 script_score 逐候选打分；有效通道标记用于候选缺少一路特征时的分支处理。

06 / ID 查重与写入一致性

在转换 PDF 和调用模型之前检查同库同 ID 是否已存在，避免已知重复记录继续消耗处理资源；最终写入设置 op_type="create"。如果两个请求同时通过前置检查，后到达的写入会收到冲突提示，从而保护已保存模板不被覆盖。此处是 ID 去重，不是文件内容去重。

匹配示例 · 仅用于解释计算

假设某候选模板的文字余弦相似度为 0.80，内容描述相似度为 0.70，则融合分数为 (0.80 + 1) × 0.4 + (0.70 + 1) × 0.6 = 1.74。服务比较候选分数并返回最高者及其标签。1.74 是排序分数，不是准确率或置信概率。当前实现返回 Top-1，未在检索链路中应用低分拒识阈值。

  • 流程编排：按时间增量查询法院公告，检查历史处理结果，使用批量迭代和条件分支控制记录流转。

展开实现细节与流程说明

01 / 从公告查询到批量处理

工作流先按时间条件查询公告，再与历史处理结果比对，避免重复处理已记录内容。将新增公告逐条送入后续节点，借助批量迭代保持统一流程，使单条数据的识别、企业查询与入库过程可以重复执行。

02 / 同时判断类型与提取要素

设计 Prompt 结合劳动法规关键词体系及公告语义，判断是否涉及劳资纠纷，并区分欠薪、社保缴纳、违法解除、加班费等类型。对符合条件的文本进一步提取总金额和涉及人数，严格限定 JSON 字段，由 Python 解析为后续节点可用的数据。

03 / 处理金额和人数歧义

在 Prompt 中约定金额单位换算、总金额与单价区分，以及人数表述的判断规则。例如“每人每月若干元”不能直接当成案件总额；“若干人共计若干万元”需要分别对应人数与总金额。通过明确规则减少把不同含义的数值混填到同一字段。

04 / 用企业库补足文本信息

公告中出现企业名称后，对接企业信息库进行匹配，并结合行政区划编码确认是否属于目标辖区。调用企业信息接口补全注册地址、省、市、区等信息，使归属判断有企业库资料支持，减少只根据公告措辞推断地址造成的偏差。

05 / 条件路由控制入库范围

在分类、企业匹配、辖区检查和接口调用等节点设置条件判断，拦截非劳资纠纷、企业缺失、辖区不匹配或接口空结果。只有满足后续处理条件的数据才继续流转，避免把不完整或无关结果直接写入劳资纠纷结果表。

06 / 封装 SQL 与接口调用

动态组织查询和写入 SQL，按接口要求进行 Base64 参数编码、MD5 验签与插件调用，将原公告、抽取字段和企业信息汇总为结构化记录。编码负责满足参数传输格式，验签遵循既有接口协议，最终由数据接口执行查询或写入。

两阶段 VLM 分类 · 合合 OCR · 来源坐标与系统对接

  • 分层分类：将 PDF/Word 转为页面 PNG，依次通过大类与细类 VLM 判断，在相应候选类别范围内确定账单类型。

  • 来源关联：将字段值关联到文件页码与原文坐标，按业务协议组织结果，支持下游定位核查和录入对接。

展开实现细节与流程说明

01 / 将不同文件统一为图片

PDF 按页渲染为 PNG；Word 先转为 PDF，再生成页面图片。这样，视觉分类面对的是统一的图像输入，同时保留页面顺序，以便后续将识别内容对应到原文件中的具体页。

02 / 先大类、再细类

一级 VLM 根据页面内容判断账单大类，二级 VLM 再在对应大类下选择细分类。分类 Prompt 提供候选类别和输出约束，减少一次判断面对过多类别的问题。分类为后续选择字段规则提供依据，不等同于已经完成所有字段抽取。

03 / OCR 提供文字与位置

调用合合 OCR 获取页面文字及对应区域坐标，并将识别内容与原文件页码关联。坐标描述文字在页面上的位置，可理解为围住文字的矩形或多边形区域。后续保留字段来源时，可以通过“第几页 + 哪个区域”找到依据。

04 / 分类与 mapping 在字段阶段汇合

不同账单类型对应不同字段定义和命名方式。结合分类结果选择规则，将 OCR 信息、字段定义和 mapping 组织进 Prompt，整理日期、币种、金额等内容并生成下游需要的标准字段。具体字段名、格式和业务编码以接口约定为准。

05 / 对接系统与人工复核

输出供业务接口消费的 JSON，并关联字段值、页码和原文坐标。下游系统可以据此将值映射到对应表单字段，也可以在复核时定位原文位置。字段坐标提供的是定位依据；页面高亮、表单填充和审核操作由下游集成环节实现。

06 / 区分分类信心与字段依据

分类输出中的“高／中／低”属于模型自评信心，可用于分类结果检查参考，不能当成校准后的准确率。字段的页码和坐标回答“值来自哪里”，与“模型有多确定”是不同信息；作品集以实际来源关联和分类输出机制分别描述。

原文回溯示例 · 示意数据

标准字段中出现“应付金额：12,000”，来源同时记录为“第 2 页，某个文字区域”。复核人员可以在原账单第 2 页找到这个区域，检查金额是否读对、是否取错了合计项。坐标用于找到证据，并不直接证明该字段一定识别正确。

展开实现细节

数据读取与特征整理

开发 TXT 读取算子，支持单文件与目录批量读取，统一到达时间、频率、脉宽和来源字段，并处理空文件、非数值及读取失败。对已分组的样本统计均值、标准差等特征，通过组内到达时间差分计算 PRI，将多条脉冲记录汇总为每组一行的特征表。

样本片段查找

以已知样本作为模板，对新数据中的候选记录进行标记，保留原始行及其位置；通过模板序列匹配比较变化模式，输出匹配位置、距离和相似度，并处理重叠结果。编写切片导出算子，将匹配片段保存为独立 TXT 文件，供后续分析读取。

样式库解析与 Top-K 匹配

读取 XLSX 样式参数库，将固定值、区间和多值枚举统一为可计算的结构。根据参数类型采用相应距离规则，与样本统计特征逐项比较，完成尺度归一化、综合距离计算及 Top-K 排序。结果用于提供候选样式，相似度分数不等同于识别准确率或概率。

聚类与结果评估

基于 scikit-learn 封装层次聚类、DBSCAN 和 OPTICS，提供特征列及算法参数配置，输出聚类标签、算法对象和散点图。DBSCAN、OPTICS 同时统计噪声比例；提供真实标签时，计算 ARI、NMI 等指标，比较聚类结果与真实分组的一致程度。

平台算子封装与接口对接

按平台组件格式声明名称、描述、输入、输出、参数和 Python 代码，让数据处理与算法能力能够在画布上连接使用。编写注册更新工具，解析算子文件并调用平台接口；更新时读取已有组件信息，匹配并保留输入、输出及参数的标识。

本地验证与可复用交付

编写本地执行夹具，模拟平台注入输入和参数、执行算子代码的过程，并配套数据读取、特征统计、匹配、聚类及组件解析测试。将业务流程拆成独立组件，统一数据字段、输出类型、错误提示和运行日志，便于后续组合与排查问题。
